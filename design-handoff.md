# Design handoff

Everything needed to build Penny's client UI in Flutter. The design track produces these; Phase 2 implements them in `packages/penny_ui` and the feature screens.

| Source | What it holds | Where |
| --- | --- | --- |
| Penny design system | Tokens, brand book, 15 components with live previews | [claude.ai artifact](https://claude.ai/artifact/LPdfpG6SV6cDd2UJkdpSV7) |
| Penny key screens | 15 screens: 11 at phone width (390), 4 at laptop width (1440), each with a light and dark theme switch | [claude.ai artifact](https://claude.ai/artifact/V1uvDiMuTjJ9YCapXr2vZZ) |
| `tokens.json` | Copy of the design system's tokens. **The source the Flutter tokens are generated from** | this folder |
| `brand-book.md` | Copy of the design system's README: the rules every screen follows | this folder |
| `components/*.md` | Copy of each component's guidelines, including its Flutter widget name | this folder |
| `screens.md` | Screen inventory mapped to routes, roles and states | this folder |

The copies here exist so an agent without access to the artifacts can still build correctly. When the design system changes, re-copy `tokens.json`, `brand-book.md` and the component guidelines in one PR titled `docs(design): sync design system`.

## Implementing in Flutter

1. **Generate tokens, do not hand-copy them.** Add `task gen:tokens`: a small Dart script in `tools/design/` that reads `docs/design/tokens.json` and writes `packages/penny_ui/lib/src/tokens.g.dart` with:
    - `PennyColors` as a `ThemeExtension<PennyColors>` with `light` and `dark` instances, one field per colour token (camelCase: `surface-sunken` becomes `surfaceSunken`). Resolve aliases such as `focus-ring` = `{copper}` at generation time.
    - `PennySpace`, `PennyRadius`, `PennySize` as classes of `static const double`.
    - `PennyShadows` for `shadow-float` and `shadow-overlay`, light and dark, as `List<BoxShadow>`.
    - `PennyText` with one `TextStyle` per type style; `time`, `time-lg` and `amount` carry `FontFeature.tabularFigures()`.
   CI's `gen:check` then fails if the generated file is stale.
2. **Build the theme** in `packages/penny_ui/lib/src/theme.dart`: `ColorScheme` from the tokens (`primary` = `ink`, `onPrimary` = `on-ink`, `surface` = `surface`, `error` = `danger`, `outline` = `border-control`, `outlineVariant` = `hairline`), `TextTheme` mapped from `PennyText`, both extensions registered, Material 3 on, splash replaced by an 8% and 12% overlay of the content colour.
3. **Fonts:** bundle IBM Plex Sans Regular, Italic and SemiBold (OFL) as assets of `penny_ui`. No runtime font fetching.
4. **Icons:** `phosphor_flutter`, Regular weight, Fill for the active navigation item. Inline SVGs in the screen designs are the same Phosphor icons.
5. **Components:** one widget per file in `components/*.md`, named as each guideline says (`PennyButton`, `LessonBlock`, `Timetable`, ...). Each gets a Widgetbook use case per state and golden tests in light and dark.
6. **Screens:** build from `screens.md`, matching the designs at 390 and 1440 wide, and checking 600 and 1024 wide where the layout switches.

## Assumptions in the designs

- Data is realistic demo data for Koh Guitar Studio on Thursday 19 November 2026 at 16:20. It matches the studio demo scenario in the build plan.
- The pixel-art app icon does not exist yet; it appears as a dashed 64 by 64 placeholder.
- The Google sign-in button shows a placeholder where Google's logo goes. Use Google's official sign-in button assets and follow their branding guidelines; do not redraw the logo.
- The PayNow QR on the public payment page is a placeholder; the real code is generated by `billing/paynow`.
