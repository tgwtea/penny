# services/api

One Go module (ADR 002). Today it builds two binaries; `worker` joins them when background jobs arrive (Phase 7).

| Binary | What it does |
| --- | --- |
| `cmd/api` | Serves the contract in `api/openapi.yaml` on `:8080` and Prometheus metrics on `:9090` |
| `cmd/migrate` | Applies goose and River migrations. Runs as a Kubernetes Job before each rollout (ADR 006) |

## Layout

```text
cmd/api, cmd/migrate   entry points: read config, wire dependencies, run
db/migrations/         goose SQL, numbered, forward-only, embedded into the binaries
db/queries/<module>/   sqlc query files, one folder per module
sqlc.yaml              generates internal/<module>/<module>sql from those queries
internal/app/          the composition root: builds every module's service
internal/apperr/       the errors services return (not found, forbidden, conflict, ...)
internal/httpapi/      generated server (gen/), thin handlers, middleware, problem mapping
internal/identity/     token verification (Firebase, emulator, test fake) and users
internal/account/      use cases about the signed-in person: /v1/me, rename, deletion
internal/platform/     config, logging, database pool and transactions, clock, health
                       checks, metrics, tracing, HTTP server, schema migrations, test databases
```

### Inside a module

Each business module (`identity`, `workspace`, `scheduling`, ...) is one package with the same shape:

| File | Holds |
| --- | --- |
| `<module>.go` | Package doc and domain types |
| `service.go` | `Service`: use cases, the transaction boundary, the `authz` check |
| `store.go` | The module's data access over its generated queries; maps rows to domain types and "no rows" to `apperr.ErrNotFound` |
| `<module>sql/` | Generated by sqlc. Private to the module (`depguard`) |

Handlers in `httpapi` call one service method and map the result; they never touch SQL (`depguard` enforces that). A use case spanning modules lives in its own small package (`account`) and calls each module's service. New modules are added to `internal/app` and nowhere else.

### Which routes need a signed-in person

The contract decides. `httpapi` reads each operation's `security` from the embedded `api/openapi.yaml`: `security: []` is public, anything else needs `Authorization: Bearer <Firebase ID token>`. The middleware verifies the token and puts the user in the request context (`userFrom(ctx)`).

## Running locally

From the repository root, with the local stack up (`task dev`):

```sh
task run:api          # applies migrations, then serves on http://localhost:8080
curl localhost:8080/readyz
```

## Configuration

Environment variables only; the process exits at startup if any is invalid, listing every problem.

| Variable | Default | Meaning |
| --- | --- | --- |
| `PENNY_DATABASE_URL` | required | `postgres://` URL. User and password may come from `PGUSER` and `PGPASSWORD` instead |
| `PENNY_HTTP_ADDR` | `:8080` | API listener (api only) |
| `PENNY_ADMIN_ADDR` | `:9090` | `/metrics` listener, never exposed through the ingress (api only) |
| `PENNY_CORS_ORIGINS` | none | Comma-separated browser origins allowed to call the API, such as the web client (api only) |
| `PENNY_SHUTDOWN_TIMEOUT` | `20s` | How long in-flight requests get after SIGTERM (api only) |
| `PENNY_FIREBASE_PROJECT_ID` | required | The Firebase project whose ID tokens are accepted (api only) |
| `PENNY_FIREBASE_AUTH_EMULATOR_HOST` | none | host:port of the Firebase Auth emulator. Makes the API accept the emulator's unsigned tokens, so it is refused unless the project ID starts with `demo-` (api only) |
| `PENNY_LOG_LEVEL` | `info` | `debug`, `info`, `warn` or `error` |
| `PENNY_LOG_FORMAT` | `json` | `json` or `text` |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | none | Turns on trace export over OTLP/HTTP. Other `OTEL_*` variables work as the SDK documents |

## Errors

Services return `apperr` kinds (`apperr.ErrNotFound`, or `apperr.New(apperr.ErrConflict, "a sentence for the user")`). `internal/httpapi/problem.go` maps each kind to one RFC 9457 problem type; it is the only place that knows status codes. Any other error is a bug: it is logged with the request ID and the client gets a 500 without detail.

## Tests

```sh
task test:api
```

Tests that need PostgreSQL use `internal/platform/schema/schematest`, which gives each test a fresh, fully migrated database (copied from a template built once per set of migrations) and drops it afterwards. They run when `PENNY_TEST_DATABASE_URL` points at a server where the role may create databases, and are skipped otherwise:

```sh
PENNY_TEST_DATABASE_URL=postgres://penny:penny@localhost:5432/penny?sslmode=disable task test:api
```

API tests (`internal/httpapi/*_test.go`) drive the generated Go client against the whole handler, wired by `internal/app` exactly as in production, with a fake token verifier (`identity/identitytest`). Tests named `...Emulator...` use real tokens from the Firebase Auth emulator and run when `PENNY_TEST_FIREBASE_AUTH_EMULATOR_HOST` is set (`localhost:9099` with `task dev` running).

CI sets all three variables and `PENNY_TEST_REQUIRE_DB=1`, which turns the database skip into a failure.

## Code generation

`internal/httpapi/gen` is generated from the contract by oapi-codegen, pinned as a Go tool in `go.mod`, and each `internal/<module>/<module>sql` package from `db/queries/<module>` by sqlc. Regenerate both with `task gen`; never edit them by hand.

## Container image

`Dockerfile` builds one distroless image holding both binaries, so the migrate Job and the API Deployment always run the same build:

```sh
docker build -t penny-api services/api
```
